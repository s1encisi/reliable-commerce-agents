# 采购决策演示

采购工作台位于 `/procurement`，旧 `/tasks` 保留查询任务的逐步执行方式。采购页确认后由服务端自动推进，页面只读事件和回执。

## 演示范围

采购同一类商品，输出最多两个独立的“单一 SKU × 数量”方案。预算是人民币商品货款，只计算一张符合条件的优惠券；不包含运费、税费，不做优惠叠加，不占券、不锁库存、不下单。评论展示可追溯原文、评分与已有标记，不把这些证据当作性能或主观偏好已满足的证明。

离线部署显示“规则解析 / 固定离线计划 / 真实数据库工具，不调用模型”。模型模式必须有服务端有效的调用预算授权，前端不代替这一检查。离线结果不能标为模型推理结果。

## 前置条件

由运行者启用本地采购功能、运行迁移，并使用 `scripts/seed_procurement.py` 向专用 `reliable_commerce_demo` 数据库追加采购样本。该脚本保留既有订单、退货和已修改库存；不要用重置数据库的方式准备演示。实际部署命令以本分支整体验收后的启动说明为准。

样本查询词为 **采购专用耳机**，主例为 **3 件、1500 元、2 个备选、最低评分 4**。用普通“耳机”会合法匹配旧样本，不能把结果差异误判为规划错误。

## 连续操作

1. 使用本地合成客户登录，打开“采购决策”。点“填入本地合成示例”，或输入上述条件，点“解析为需求草案”。
2. 核对检索词、数量、总货款预算和备选数量。规则解析没完整保留查询词时，把检索词明确改为“采购专用耳机”。数量或预算缺失不会被页面自动补齐。不支持的硬条件必须修改原需求并重新解析。
3. 勾选核对确认，点击“确认并自动启动”。页面依次保存一致的目标和结构化需求、确认需求、启动服务端执行，所有后续请求使用上一次响应的版本。
4. 查看计划层、节点状态、步骤来源、模型调用数、修复次数和复用证据数。报价、库存和评论来自不同专业服务，最终方案以事实核验结果为准。
5. 执行中可点“暂停任务”。状态真正变成“已暂停”后，将预算改为 1200 元，重新勾选核对并确认启动。已过期或与新条件不相容的回执不能直接证明新结果。任务若已结束，可点“修订需求”进入暂停态后更改条件；演示中必须说明这是完成后修订，不将其录成执行中暂停。
6. 对比两个独立方案的优惠前货款、单券优惠、最终货款、可售/需求数量与评论引用。查看失败、历史计划、过期证据时，以其标识为准。
7. 刷新页面或保留 `?task=<UUID>` 链接恢复任务。实时连接断开后可续接事件或手动刷新；这不会重放确认、启动、暂停请求。
