# 发布与隐私边界

公开内容仅包括源码、许可证、经过检查的项目文档、合成测试样例、合成演示截图和可复验的指标。

## 留在本机

- 真实 `.env`、API 密钥、登录状态、证书与凭据。
- 客户或业务数据、数据导出、数据库及备份、私人 Office/PDF 文件。
- `.claude/`、`.codex/`、`.agents/`、`.local/` 中的个人计划、工具状态和运行日志。
- `.git/` 内原始历史备份、扫描报告和本机推送策略。

私有目录限制为当前用户访问，环境与登录文件采用最小文件权限。访问权限保护不等同密码学加密；
不将加密过的私有文件作为可以公开上传的理由。真实配置和数据不进入版本控制。

## 发布前检查

```bash
python3 scripts/audit_publication.py --ref HEAD
```

需要 Gitleaks 可执行文件位于 PATH 或 `.local/bin/gitleaks`。脚本只在被 Git 排除的目录保存扫描结果，
检查将公开的提交历史、当前源码快照、禁止文件及链接。发布还需检查远端其他分支、issue/PR、附件、工作流产物和图像来源。

本机推送检查限定到当前授权的 origin 和独立开发分支，扫描整段待推送历史；不使用 `git add -f`，
不推送所有旧分支、标签或历史备份。`.gitignore` 不能代替历史审查和密钥扫描。

本轮开发分支为 `feat/after-sales-reliability`，没有合并到 `main/master`。上游作者和 MIT 许可证保留。
扫描可以识别常见密钥与禁止路径，但不能自动证明不存在所有商业秘密；二进制文件和新增数据仍需要人工核对。

## 自动化

GitHub Actions 当前保持关闭。仓库提供新的 `portfolio-ci.yml` 验证配置；本轮报告来自本地实际运行，
不宣称远端 CI 已通过。继承的发布、文档部署、镜像和包清理任务需要维护者另行审查后再授权启用。

具体测试、对照与发布审查结果见 [验证记录](verification.md)。
