# Python 学习指南：从现有代码建立判断能力

## 目标与协作方式

目标是通过阅读、修改和验证现有代码，理解 Agent 系统的工具调用、业务规则与恢复流程。阶段以掌握和验收为准。

每次学习只推进一个小阶段：

1. 说明业务问题、为什么现在处理、影响文件和输入输出。
2. 读少量关键函数，沿实际调用关系理解。
3. 学习者先判断正常与异常情况下应该发生什么。
4. 编程搭档生成最小改动并运行适当测试。
5. 解释差异、失败与证据，学习者复述后再进入下一阶段。

不要求从空白手写函数。重点是理解、修改、调试和结果判断，避免把生成代码当作不能审阅的黑箱。

## 阶段地图

| 阶段 | 阅读材料 | 验收 |
|---|---|---|
| 1：模型与工具 | 教程 01、02 | 解释工具定义、模型请求、框架执行和真实数据来源 |
| 2：售后规则 | 售后代码导航、return_tools.py | 用例描述允许 / 拒绝 / 待核实，找出入口差异 |
| 3：执行恢复 | idempotency.py、http_resilience.py | 区分技术异常、业务拒绝与结果未知 |
| 4：评估与展示 | 教程 24、26、可靠性方案 | 解释基线、故障注入、消融和局限 |

每周结合代码补齐 Python 类型标注、异常、异步、SQL、HTTP、Git 和 Linux 基础。框架名词服务于具体问题，不以记忆 API 名称代替理解。

## 第一个 40 分钟

打开 [第 02 章代码](../../tutorials/02-add-tools/python/main.py)，按以下顺序阅读：

1. get_product_price：价格来自固定字典；不存在的 SKU 返回提示。
2. @tool：把函数名称、描述和参数格式提供给框架。
3. build_agent：把模型客户端、指令和工具组合起来。
4. ask / main：接收问题、运行智能体并返回回答。

这章 SKU-001 的固定数据是 79.99 美元；不要与其他章节的商品数据混用。

你需要解释：模型是否亲自执行 Python？写在提示词里的要求是否构成硬约束？回答正确是否足以证明调用了工具？

## 进入售后改进之前

先完成一个原版反例，不同时修改所有入口。推荐从“缺签收记录却被判可退”开始，使用合成数据，比较源码预期与实际返回。

方案中的政策默认值是教学项目的设计选择，不能冒充平台真实运营政策或法律要求。业务判断由学习者参与确认，程序实现与验证由编程搭档协助。
